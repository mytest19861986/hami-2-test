# Eligibility API

`POST /api/v1/providers/:providerId/eligibility/check` is the provider-operated lookup: it accepts a customer's National ID, requires an active authenticated `ProviderMembership` for that exact APPROVED provider, normalizes/checks the ID, and matches only `UserProfile.nationalId`. The legacy `User.nationalId` column is not consulted. Invalid, unknown, and ineligible IDs return the same `{ eligible: false }` shape; an eligible result returns a member display name and applicable benefits but never the submitted/raw National ID. Audit records contain no ID or identity fingerprint.

`GET /api/v1/providers/:providerId/eligibility` is the customer self-check and uses the authenticated user ID, not a supplied National ID. Redemption initiation and confirmation are session/membership scoped and re-evaluate current provider, purchase, membership, and benefit state. The cataloged `eligibility.check` permission does not grant access to the legacy provider-operated check route; active provider membership on the requested provider is its authorization boundary.

`POST /api/v1/providers/eligibility/doctor` is the public exact-National-ID Doctor eligibility lookup. Invalid IDs receive a controlled 400; a valid but unknown, pending, rejected, suspended, or otherwise non-approved Doctor returns `{ eligible: false }`. An approved Doctor returns only public provider ID, display name, specialty, province, and city. Raw/masked National ID, HMAC digest, council number, and internal review metadata are never returned or written to audit logs. The endpoint is IP-rate-limited by the current local in-memory limiter (five requests per minute); this is suitable only for LOCAL/TEST and must be replaced with a shared distributed limiter before production.
