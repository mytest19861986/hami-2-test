# Eligibility API

`POST /api/v1/providers/:providerId/eligibility/check` is the provider-operated lookup: it accepts a customer's National ID, requires an active authenticated `ProviderMembership` for that exact APPROVED provider, normalizes/checks the ID, and matches only `UserProfile.nationalId`. The legacy `User.nationalId` column is not consulted. Invalid, unknown, and ineligible IDs return the same `{ eligible: false }` shape; an eligible result returns a member display name and applicable benefits but never the submitted/raw National ID. Audit records contain no ID or identity fingerprint.

`GET /api/v1/providers/:providerId/eligibility` is the customer self-check and uses the authenticated user ID, not a supplied National ID. Redemption initiation and confirmation are session/membership scoped and re-evaluate current provider, purchase, membership, and benefit state. No provider/doctor National ID field or separate Admin National-ID lookup route exists. The cataloged `eligibility.check` permission does not grant access to the legacy check route; provider membership on the requested provider is the effective authorization boundary.
