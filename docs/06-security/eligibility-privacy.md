# Eligibility Privacy

The eligibility boundary resists National-ID enumeration, provider IDOR, expired/cancelled/refunded membership reuse, and sensitive audit leakage. Matching uses only the unique `UserProfile.nationalId`; the legacy `User.nationalId` field is not consulted. Provider-operated checks require membership on that exact APPROVED provider. Invalid, unknown, and ineligible input share the same response shape. Raw National IDs are not returned in profile, auth, admin, provider, eligibility, redemption, reporting, or audit responses. Audit records may retain actor/provider scope, result, timestamp, and non-sensitive reason only; this flow does not persist an ID or identity fingerprint. Public provider projection exposes safe catalog fields and omits the Doctor medical council number.
